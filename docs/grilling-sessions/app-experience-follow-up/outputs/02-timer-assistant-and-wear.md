## Evidence

- `ExpandedIntentionsPicker.tsx` currently gives Break and Long-break Timers nine parent slots, but Work gets six at top placement and on short bottom layouts (`window.innerHeight < 700`).
- `Timer.tsx` moves the expanded picker to top placement when the Minimized task view is present, making current Work density depend on surrounding composition.
- `ExpandedIntentionsPicker.tsx` already has a partial short Break/Long-break compact path that reduces button height, gaps, and padding; it does not apply consistently to Work.
- `ExpandedIntentionsPicker.tsx` renders the Sub-intention band as `grid-cols-6` with independent previous/next controls.
- `DESIGN.md` asks primary workflows to fit above the fold and discourages scrolling.
- `window.ts` currently defines `EXPANDED_HEIGHT = 690`; `uiStore.ts` uses that constant for normal and Linux expansion paths.
- `Timer.tsx` currently positions the desktop Timer stage with fixed 210 px upper/lower panel reservations and a 10 px downward transform, while top navigation and picker placement use separate absolute offsets.
- `MinimizedIntentionsPicker.tsx` currently changes Break/Long-break page size from four to three whenever `timer.isExtension` or `extensionState` is present; compact Minimized-task mode independently uses three.
- `TimerActionButtons.tsx` renders the minimized extension action in the same right-side action region as Timer controls.
- `useKeyboardShortcuts.ts` already opens extension options with `Mod+D`, while `TimerActionButtons.tsx` still displays `T`; `Mod+T` is the Tasks shortcut.
- `TimerActionButtons.tsx` currently requires `remainingTime === duration`, which removes the minimized action after the Timer has run or its duration has changed.
- `timer.service.ts` creates extension state only after a non-extension Work Timer completes, preserves it through Break/Long break, clears it when new Work starts, and prevents extension Timers from spawning another extension opportunity.
- `MinimizedTaskView.tsx` already sends advanced creation from compact mode through a cross-shell request, but edit currently keeps local `editingTaskId` and mounts `TaskFormModal` inside the compact shell.
- `AssistantLauncher.tsx` currently owns `MediaRecorder`, elapsed time, submission, result, and error locally; it is mounted only from `Timer.tsx`, and unmount cleanup cancels recording.
- Existing non-Timer pages use left-aligned `BackButton` variants with different header structures, so active Assistant placement needs a shared heading primitive or equivalent consistent slot.
- `AssistantLauncher.tsx` currently renders a fixed modal-like card containing stage text, elapsed/max duration, transcript, message, Close, and a large Stop/Record action.
- ADR 0012 requires Assistant mutations to remain visible through terminal lifecycle and reconcile confirmed state; accepted/running work is not a dismissible local recording state.
- `userActionQueue.ts` and `WatchActionCoordinator` use in-memory FIFO submission and confirmed reconciliation; neither should persist unsent Assistant audio for replay.
- `AssistantActivity.kt` already uses a full-width 60 dp bottom control with a separate Cancel control above, but its active text is microphone + `Listening` + elapsed rather than stop square + `Stop` + elapsed.
- `AssistantActivity.kt` currently calls `cancelRecording()` from `onPause`, which conflicts with the shared background-as-auto-Stop decision.
- `WatchControlPresentation` currently sizes Long break and other secondary app actions at 40 dp and Play/Pause at 48 dp; Tile uses a compact peer size when five actions are present but currently ties hit bounds to visual size.
- `WatchFaceActivity.kt` currently renders the empty glyph at 18 sp after status render; `PomiTileService.kt` uses 20 sp. Both already wrap it in a larger Intentions control.
- `WatchFaceActivity.setLoading()` currently disables `intentionsRow` with Timer mutation controls, even though the row only navigates to `IntentionsActivity`; ADR 0012 permits navigation while actions queue.
- `WatchFaceActivity.kt` and `PomiTileService.kt` are separate renderers. They reuse `WatchHomePresentation`, `WatchRingPresentation`, `WatchColors`, and some queue helpers, but still define independent geometry and enabled/click logic that can drift.
- `WatchHomeStateTest.kt` already provides a pure Kotlin contract-test seam for ring math, presentation constants, control positions, and Assistant geometry; coverage does not yet prove full app/Tile state parity.
- `deploy-watch.sh` currently retries the stored address after restarting ADB, then immediately prints only a re-pair guide; README documents main and pairing ports separately but does not present the requested ordered combined recovery flow.
- `deploy-watch.sh` currently performs one normal `adb install -r` attempt and reports only a warning on failure; it does not verify device identity after recovery, try non-streaming install, or print focused transport diagnostics.

## Proposed CONTEXT.md changes

- Add **Timer extension**: Additional Work time attributed to the just-completed Work Timer and resolved from the following Break or Long-break context. It may log elapsed extension time or continue with more Work time; a Timer extension does not recursively create another extension opportunity.
- Add **Assistant recording**: An application-scoped voice capture session. Stop submits captured speech; Cancel discards it. In-app navigation and transient connection loss preserve capture, maximum duration or app backgrounding auto-Stop, and authentication loss cancels it.
