## Evidence

- `packages/backend/scripts/seed-user-fixture.ts` currently bcrypt-checks the password, compares every expected preference, loads and validates every seeded Intention and parent link, aggregates statistics counts and latest completion time, compares every expected Task field, and loads Task events before reporting a healthy fixture.
- `scripts/start-project-frontend.sh` and `scripts/start-worktree-environment.sh` both run `pnpm --filter @pomi/backend seed:copyme` during normal startup, so the broad health check directly delays every development launch.
- `packages/backend/scripts/seed-copyme-user.ts` fixes Copyme's admin contract and derives credentials from environment variables, so the marker lookup must cover admin state and the active credential configuration as well as seed version.
- The current statistics generator is relative to the day of each full seed (`TEST_STATISTICS_DAYS = 365 * 3 + 30`) and the current health check requires a statistic from today. That conflates structural health with freshness and causes otherwise healthy state to be discarded.
- Current full reseed deletes all Copyme statistics before regenerating them, which matches the accepted explicit-only freshness policy but requires clear destructive-command wording.
- `PreferencesService.updatePreferences` forces `autoStartBreak` false whenever `timerExtension` is enabled, so a literal all-true profile is not a valid product state.
- `assistantTaskTranscriptsEnabled` keeps exact relevant source text on AI-created Tasks. Persistent AI debug logging is stored separately in `assistant_debug_settings`, defaults off under ADR 0005, and is therefore an explicit Copyme-only fixture exception rather than an ordinary preference default.
- Current Copyme preferences omit `tasksDuringBreaks` and leave `undoAlerts` false. The current seeded Task assignment resolver hardcodes Work Intentions, so Break and Long-break Task behavior is not yet represented by data.
- Session progress is stored in Redis by `TimerStore` and initialized by Timer behavior when Sessions are enabled. Database seeding should therefore configure the feature without manufacturing ephemeral runtime state.
- Assistant model/key/budget configuration is global in `assistant_settings`, while Copyme's Assistant and transcript preferences are per-user. The fixture must not claim Assistant is externally configured merely because its user capability is on.
- `DebugPanel.loadAssistantDebugState` currently sets `isAssistantDebugLoading = true` for initial load and every refresh. Rendering then replaces the whole list with `Loading logs...`, explaining the disappearing/reappearing rows and page-height oscillation.
- Flagging currently patches the matching row locally, while toggle and clear register full-state reconciliation callbacks. The accepted design generalizes the targeted confirmed update and removes unnecessary teardown refetches.
- `AssistantDebugService.listLogs` returns stable UUIDs ordered newest-first and includes flagged logs beyond the normal recent-50 window, providing the stable identity required to preserve expansion and anchor position during reconciliation.

## Proposed CONTEXT.md changes

- Propose **Fixture marker** — durable metadata certifying that a named development fixture was fully written for a particular seed version. _Avoid_: Seed date, fixture health scan. This is specific to Pomi's local fixture lifecycle; no root `CONTEXT.md` edit is made during grilling.

## Cross-track implications

- Any other local fixture intended to preserve developer-authored state must choose its own lifecycle; Copyme's disposable auto-heal rule must not silently generalize to William or product users.
- Package/script naming must distinguish the public force-reseed workflow from the internal startup ensure path without adding another user-facing diagnostic workflow.
- Debug flag/clear/toggle changes must preserve ADR 0012's confirmed action semantics while avoiding whole-list reconciliation; this may require the mutation result to carry the changed row/status rather than forcing a refetch.
