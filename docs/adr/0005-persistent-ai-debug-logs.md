# Retain Administrator Capture Logs Behind Fresh Consent

Pomi persists AI Task capture diagnostics only when the signed-in administrator enables Capture logs from Admin. Consent is versioned and starts disabled after this policy change; an older debug-enabled setting never counts as content consent. Each capture records the consent generation at request start and rechecks administrator status, consent, ownership, and generation under a per-user transactional lock before persistence.

Capture logs stay off by default and store only submitted typed text or a submitted transcript, allowlisted normalized Task/List-item output, a metadata-only outcome category, and available stage timings. They never store raw audio, generated spoken-reply audio, full model requests or responses, provider envelopes, system prompts, credentials, expanded Task or Intention context, raw parser failures, arbitrary exception messages, or unrelated Assistant timer commands. Diagnostic content is excluded from Sentry, console logs, and general action-event payloads.

Task-view dictation and its eventual Task capture share one entry. A successful dictation that is never submitted remains as a dictated-only entry; final submission replaces it with the submitted prompt without losing its flag. The backend keeps the latest 50 unflagged entries plus at most 200 explicitly flagged entries. Input and normalized output are size-limited with a visible truncation marker. Flagged export is owner-constrained. Clear deletes all logs, including flags. Disabling serializes against recording, advances the generation, deletes all of that administrator's logs, and prevents late in-flight captures from restoring them. Imported diagnostics remain scrubbed and disabled; historical content removed by migration is never reconstructed.
